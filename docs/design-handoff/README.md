# Handoff: Dr. GL — GL 콘텐츠 큐레이션 플랫폼 + 운영 어드민 (전체 기능 최종본)

## Overview
Dr. GL은 영화·드라마(국내/해외)·웹툰·웹소설·소설·애니·만화 등 GL(백합) 콘텐츠를 한곳에 모아 소개·추천하고, 어디서 볼 수 있는지 연결해주는 콘텐츠 큐레이션 플랫폼입니다. 이 문서는 **사이트(이용자용)와 어드민(운영자용) 두 화면 묶음의 모든 기능**을 빠짐없이 기술합니다. 이전 버전 대비 제보 검토·발행 플로우, 한줄평(비로그인 리뷰), 출연진 교차 추천, 실제 시청 링크, 카테고리 동적 관리 등이 모두 추가된 최종 상태입니다.

두 화면 묶음은 프로토타입 상에서 **동일한 데이터 저장소(브라우저 localStorage)를 공유**하며, 어드민에서 만든 변경이 사이트에 실시간 반영되도록 만들어져 있습니다. 실제 서비스에서는 이 부분을 진짜 서버 API + DB로 교체해야 합니다 (아래 "데이터 계층" 섹션에 정확한 교체 지점을 명시).

## About the Design Files
이 번들의 HTML 파일들은 **디자인 레퍼런스**입니다 — 실제 동작하는 프로토타입이지만, 그대로 복사해 쓰는 프로덕션 코드가 아닙니다. 대상 코드베이스(예: Next.js/React + 서버 API + DB, 또는 팀이 이미 쓰는 스택)의 기존 패턴과 라이브러리로 **다시 구현**하세요. 정해진 스택이 없다면 아래 "권장 백엔드 아키텍처"를 참고해 프레임워크를 선택하세요.

## Fidelity
**High-fidelity.** 색상·타이포그래피·간격·인터랙션이 최종안 수준입니다. 픽셀 단위로 재현하는 것을 목표로 하세요.

# PART 1 — 사이트 (이용자용)

## 공통 헤더 (모든 화면)
- 좌측: 로고 "Dr. GL"(보라색 "GL") — 클릭 시 홈으로.
- nav: 홈 / 카테고리 / 게시판("OPEN 예정" 배지) / **+ 제보하기**(CTA 버튼, nav 그룹 안에 위치 — 검색창 옆에 두면 검색 버튼처럼 오인되어 nav 안으로 이동시킴). 현재 화면에 해당하는 nav 항목은 굵게/흰색으로 활성 표시.
- 우측: 검색창(돋보기 아이콘 + input). 입력 중 Enter 또는 값 변경 시 검색 화면으로 전환(단, 상세/게시판 화면 위에서 입력 시작한 경우에도 자동으로 검색 화면 전환).

## 1. 홈
- 히어로 배너(520px): featuredId로 지정된 콘텐츠(기본 "아가씨")의 배경 이미지(또는 "포스터 준비중" 텍스트 타일) + 카테고리 pill + 국가·연도 + 제목(44px) + 줄거리 2줄 요약 + "상세보기"/"시청 가능한 곳" 버튼(둘 다 상세 페이지로 이동).
- 가로 스크롤 콘텐츠 행 4개(각 제목별로 지정된 id 목록 기반): "이번 주 추천", "착즙 인생작 · 서브도 진심이야", "웹소설 · 웹툰 원작 인기작", "해외 콘텐츠 모음". 존재하지 않거나 삭제된 id는 자동으로 건너뜀(행 자체가 비면 행도 숨김).
- 각 카드는 `ContentCard` 컴포넌트: 4:3 썸네일(포스터 없으면 그라디언트 배경의 "포스터 준비중" + 제목 텍스트 타일) + 카테고리 pill + "착즙" 배지(해당 시) + 제목 + 연도·제작자 + 출연진 이름(1줄, 말줄임).

## 2. 카테고리 탐색
- 형식 필터 칩: 전체 + 카테고리 관리에서 정의된 카테고리 전부(동적).
- 국가 필터 칩: 전체/국내/해외.
- "착즙만 보기" 토글.
- 위 조건을 모두 만족하는 콘텐츠를 반응형 그리드로 표시. 결과 없으면 안내 문구.

## 3. 검색 결과
- 헤더 검색창과 연동. 검색어가 제목/제작자/카테고리/태그 중 하나에 포함되면 매치.
- 검색어 있음 + 결과 있음: "'검색어' 검색 결과 N건" + 그리드.
- 검색어 있음 + 결과 없음: 안내 문구.
- 검색어 없음: "찾고 싶은 작품을 검색해보세요" + 추천 태그 칩(#오피스 #학원 #로맨스판타지 #시대극 #착즙) — 클릭 시 그 태그로 즉시 검색.

## 4. 콘텐츠 상세
URL: `Dr GL.dc.html?detail=<콘텐츠id>` 로 직접 진입 가능(딥링크). 파라미터가 있고 유효한 id면 초기 화면이 바로 해당 상세 페이지로 렌더링됨(어드민의 한줄평 검수에서 "사이트에서 보기"를 누르면 이 방식으로 새 탭이 열림).

- **배경 배너**(440px): 배경 이미지(또는 준비중 타일) + 카테고리·착즙 배지·국가·연도 + 제목(38px) + 제작자 구분+이름.
- **좌측 컬럼** (순서대로):
  1. 줄거리
  2. **출연** — leads 배열을 pill로 표시(배우/주인공 이름. 영화·드라마·애니는 실제 배우, 웹툰·웹소설·소설은 주인공 이름으로 사용).
  3. 태그
  4. **한줄평** (아래 상세 설명)
  5. "이런 작품은 어때요?" — 같은 카테고리의 다른 콘텐츠 최대 6개.
  6. **"{배우/주인공 이름}의 다른 작품"** — 현재 콘텐츠의 출연진 중 한 명이라도 겹치는 다른 콘텐츠가 있을 때만 노출(최대 6개). 예: "밤의 화원"과 "부실장님과 나"는 배우 "진세은"을 공유하도록 시드 데이터에 반영되어 있어, 서로의 상세 페이지에 이 섹션이 뜸.
- **우측 컬럼(sticky 카드)**: "시청·감상 가능한 곳" — 플랫폼별 행. **행 전체가 클릭 가능한 링크**이며, 플랫폼에 실제 URL이 등록되어 있으면 새 탭으로 열림(외부 링크 아이콘 표시). URL이 없으면 클릭해도 아무 동작 없음(안전 가드).

### 한줄평 (핵심 기능 — 비로그인)
- 로그인 없이 누구나 텍스트만 입력해 즉시 남길 수 있음(입력창 + "남기기" 버튼, 빈 값 제출 방지).
- 표시 형식: 화려한 카드가 아니라 **간결한 한 줄 리스트** — 왼쪽에 작성일(YYYY.MM.DD), 오른쪽에 내용, 아래 옅은 구분선. "익명" 같은 라벨은 쓰지 않음(날짜가 그 역할을 대신함).
- 최신 항목이 배열 뒤에 쌓이는 구조지만 표시는 저장 순서 그대로(최근 작성 여부와 무관하게 등록 순). 콘텐츠당 한줄평이 **5개 초과** 시 처음 5개만 보이고 "더보기 (N)" 버튼이 나타나며, 누르면 전체가 펼쳐지고 버튼은 "접기"로 바뀜. 다른 콘텐츠 상세로 이동하면 펼침 상태는 초기화됨.
- 어드민에서 "숨김" 처리한 한줄평은 이 목록에서 제외됨(soft-hide).

## 5. 콘텐츠 제보하기
- 진입: 헤더의 "+ 제보하기" 버튼.
- 폼 필드: 작품 제목(필수), 형식(카테고리 칩, 동적 목록), 국가(국내/해외 칩), 착즙 여부(토글), 시청/감상 링크(필수, URL), 구글 드라이브 안내 링크(공식 링크가 없을 때를 위한 안내 문구 + `https://drive.google.com` 링크), 제보 사유·한줄 코멘트(선택), 답변 받을 이메일(선택).
- 제목/링크 미입력 시 제출 차단 + 인라인 에러.
- 제출 시 제보가 공유 저장소의 `submissions` 큐(`status:'pending'`)에 들어가고, "제보 완료! 검토 후 등록할게요" 안내 화면으로 전환("제보 하나 더 하기" / "홈으로" 버튼 제공). 이 제보는 **어드민의 "제보 검토" 화면에 즉시 나타남**(다른 탭이어도 실시간 반영).

## 6. 게시판 (오픈 전)
- 커뮤니티 게시판 준비중 안내 화면. 비활성(회색, 클릭 불가) 카테고리 미리보기 칩(자유게시판/작품 후기/추천 요청/착즙 정보 공유) + 오픈 알림 이메일 신청 폼(제출 시 확인 문구로 전환, 실제 발송 없음).

# PART 2 — 어드민 (운영자용)

레이아웃: 좌측 고정 사이드바(232px) + 우측 콘텐츠 영역. 사이드바 nav: 대시보드 / 콘텐츠 관리 / 카테고리 관리 / 제보 검토(대기 건수 배지, 0건이면 배지 숨김) / 한줄평 검수. 사이드바 하단에 "사이트와 동일한 저장소를 사용해요..." 안내 문구.

## 1. 대시보드
- 통계 카드 4개: 전체 콘텐츠 수 / 대기중인 제보 수(강조색) / 노출중인 한줄평 수 / 카테고리 수.
- "대기중인 제보" 미리보기(최신 3건 제목) + "전체 보기 →" 링크(제보 검토로 이동).
- "최근 한줄평" 미리보기(최신 3건, "콘텐츠명 · 내용") + "전체 보기 →" 링크(한줄평 검수로 이동).

## 2. 콘텐츠 관리
- 상단 "+ 콘텐츠 추가" 버튼.
- 필터 바: 제목 검색 입력 + 카테고리 필터 칩(전체 + 동적 카테고리 목록) + **"착즙만 보기" 토글**.
- 테이블: 썸네일(38×38, 포스터 없음이면 "-" 표시) / 제목 / 카테고리 / 국가·연도 / 착즙 배지 / 관리(수정·삭제).
- 결과 없으면 안내 문구.

### 추가/수정 모달 (공용 폼)
필드 순서: 제목 → 카테고리(select, 동적 목록) + 연도 → 국가(국내/해외 칩) → 국가 상세(자유 텍스트) → 제작자 구분(감독/연출/작가 칩) → 제작자 이름 → 출연·주인공(쉼표 구분 텍스트, 저장 시 배열 변환) → 태그(쉼표 구분 텍스트) → 착즙 토글 + **"포스터 이미지 사용" 토글** → (토글 켜져있고 기존 콘텐츠 수정 중일 때만) **카드 썸네일 업로드** — 사이트의 카드가 쓰는 것과 **동일한 slot id**(`poster-{id}`)를 사용하므로 여기서 올린 이미지가 사이트에도 그대로 반영됨 → 줄거리(textarea) → **시청·감상 가능한 곳**(플랫폼별로 이름 입력 + **실제 URL 입력** + 무료/유료 토글 + 행 삭제 버튼, "+ 링크 추가"로 행 추가).
- 저장 시 제목·카테고리 필수 검증(실패 시 인라인 에러). 새 콘텐츠는 id 자동 채번(`기존 최대 id + 1`).
- 신규 추가 시에는 썸네일 업로드 UI가 보이지 않음(아직 id가 없어 slot을 만들 수 없음) — 저장 후 다시 "수정"으로 열면 업로드 가능.

## 3. 카테고리 관리
- 새 카테고리 이름 입력 + "+ 추가"(중복 이름이면 에러).
- **안내 배너**: "착즙"은 카테고리가 아니라 콘텐츠별 토글이라는 점을 명시(운영자가 착즙을 카테고리로 착각해 추가하는 걸 방지).
- 목록: 카테고리명 + 사용중인 콘텐츠 수 + "이름변경"(인라인 편집: 입력창으로 바뀌고 확인/취소 버튼) + "삭제".
- **이름 변경 시 해당 카테고리를 쓰는 모든 콘텐츠의 category 필드가 함께 갱신됨(cascade)**.
- **삭제는 해당 카테고리를 쓰는 콘텐츠가 1개 이상이면 차단**되고 몇 개가 걸려있는지 에러 메시지로 안내.

## 4. 제보 검토
- 필터 탭: 대기중(기본) / 승인됨 / 반려됨 / 전체.
- 각 제보: 제목 + "형식 · 국가" pill + 착즙 배지 + 상태 pill, 코멘트(제보자가 남긴 사유, 없으면 "코멘트 없음"), 링크(클릭 가능한 실제 URL), 연락처(없으면 "없음"). 대기중 항목에만 **"검토 · 발행"** / "반려" 버튼 노출.
- **"검토 · 발행" → 콘텐츠 추가/수정과 완전히 동일한 모달이 열림** — 제보 데이터(제목/카테고리/국가/착즙 여부/코멘트→줄거리 초안/링크→플랫폼 1행)로 미리 채워져 있고, 모달 상단에 **"제보 원본(참고용)"** 패널(원본 링크 + 연락처, 읽기 전용)이 추가로 표시됨. 운영자가 부족한 정보(연도, 제작자, 출연진, 태그, 추가 플랫폼, 썸네일 등)를 채운 뒤 **"승인 및 발행"** 버튼을 누르면 — 새 콘텐츠가 실제로 생성되고 **동시에** 해당 제보가 `승인됨` 상태로 바뀜(하나의 저장 동작으로 두 가지가 함께 반영).
- "반려": 모달 없이 즉시 해당 제보를 `반려됨` 상태로 변경(콘텐츠는 생성되지 않음).

## 5. 한줄평 검수
- 필터 탭: 전체(기본) / 노출중 / 숨김.
- 각 행: **콘텐츠 제목("· 사이트에서 보기 ↗" 표시, 보라색 클릭 가능 텍스트)** — 클릭 시 **사이트를 새 탭으로 열어 해당 콘텐츠의 상세 페이지로 바로 이동**(`Dr GL.dc.html?detail=<id>`), 실제로 그 한줄평이 달려 보이는 화면까지 확인 가능 / 한줄평 내용(1줄 말줄임) / **작성 시각**(YYYY.MM.DD HH:mm) / 상태 pill(노출중·숨김) / "숨기기"·"노출하기" 토글 버튼 / "삭제"(확인 후 영구 삭제).
- "숨김" 처리된 한줄평은 사이트 상세 페이지에서 즉시 사라짐(사이트가 같은 저장소를 읽기 때문).
- 데모용으로 5개의 예시 한줄평이 미리 채워져 있음(아가씨 2건, 너와 나의 계절/회귀한 대공님/부실장님과 나 각 1건, 그중 1건은 "숨김" 상태 예시).

## Interactions & Behavior (공통)
- 모든 입력은 controlled input. 필수 필드 누락 시 제출을 막고 인라인 에러 텍스트를 보여줌.
- 파괴적 동작(콘텐츠 삭제, 카테고리 삭제, 한줄평 삭제)은 브라우저 `confirm()` 다이얼로그로 재확인. 프로덕션에서는 자체 확인 모달 + 실행취소(undo) 토스트 권장.
- 카드/행 hover: 미묘한 밝기 변화 또는 살짝 위로 이동(translateY) + 그림자 강조.
- 로딩/에러 상태는 프로토타입에 없음(로컬 데이터라 즉시 반영). 실서버 연동 시 각 CRUD 액션에 로딩 스피너 + 실패 토스트 필요.
- 카테고리·제보·한줄평 어디에도 서버 응답 지연이 없다는 전제이므로, 실제 구현 시 낙관적 업데이트(optimistic update) + 실패 롤백 패턴을 권장.

## 데이터 계층 (가장 중요한 섹션)

### 프로토타입의 동작 방식
사이트와 어드민 두 파일은 브라우저 `localStorage`의 **동일한 키 `drgl_store_v1`**을 공유 저장소처럼 사용합니다.

```json
{
  "items": [ /* 콘텐츠 배열 */ ],
  "categories": [ "영화", "드라마", "웹툰", "웹소설", "소설", "애니", "만화" ],
  "submissions": [ /* 제보 배열 */ ],
  "comments": [ /* 한줄평 배열 (플랫 배열, itemId로 콘텐츠와 연결) */ ]
}
```

- 최초 로드 시 저장된 값이 없으면 시드 데이터(콘텐츠 18개 + 기본 카테고리 7개 + 데모 한줄평 5개)로 채움.
- 모든 쓰기(추가/수정/삭제/승인/반려/숨김 등)는 `persist()` 헬퍼로 React state와 `localStorage`를 함께 갱신.
- 브라우저 `storage` 이벤트를 구독해서 **다른 탭에서 어드민이 데이터를 바꾸면 사이트 탭도 즉시 갱신**됨(같은 브라우저 내 시뮬레이션 — 서버가 없으므로 다른 기기/브라우저 간에는 동기화되지 않음).
- 콘텐츠 상세 페이지는 URL 쿼리 파라미터 `?detail=<id>`를 읽어 초기 화면을 해당 상세로 바로 띄움 — 어드민의 한줄평 검수 "사이트에서 보기" 기능이 이 방식으로 새 탭을 엶.
- 이미지(포스터/배경)는 `<image-slot>` 컴포넌트로 드래그 앤 드롭 업로드를 흉내냄. **사이트 카드와 어드민 수정 모달이 같은 slot id(`poster-{id}`)를 쓰기 때문에 어드민에서 올린 이미지가 사이트 카드에도 그대로 보임.** 이 메커니즘은 이 툴체인 특유의 임시 저장 방식(sidecar 파일)이며, **프로덕션에서는 완전히 실제 이미지 업로드/스토리지(S3, Cloudinary 등)로 교체**해야 함.

### 프로덕션에서 반드시 교체해야 할 것
`localStorage` + `storage` 이벤트 + `<image-slot>` 조합을 다음으로 대체:

1. **백엔드 API 서버** (REST 또는 GraphQL). 최소 엔드포인트:
   - `GET/POST/PATCH/DELETE /content` — 콘텐츠 CRUD (필드는 아래 스키마 참고)
   - `GET/POST/PATCH/DELETE /categories` — 카테고리 CRUD (이름 변경 시 서버에서 연관 콘텐츠 cascade 업데이트)
   - `GET/POST /submissions`, `PATCH /submissions/:id` — 제보 등록/상태 변경(pending→approved/rejected)
   - `POST /submissions/:id/publish` — 제보 승인과 동시에 콘텐츠 생성(어드민의 "검토·발행" 동작에 대응, 트랜잭션으로 처리 권장)
   - `GET/POST /comments`, `PATCH /comments/:id`(visible/hidden 토글), `DELETE /comments/:id`
   - 이미지 업로드용 presigned URL 발급 엔드포인트 (`POST /uploads`)
2. **DB 스키마**는 아래 참고.
3. **즉시 반영 방식**: (a) 캐시 없이 매 요청마다 서버에서 최신 데이터 조회, (b) 웹소켓/SSE로 변경 이벤트 push, (c) 짧은 주기 폴링 + 캐시 무효화 — 완전한 실시간이 필수가 아니라면 (a)로 충분.
4. **어드민 인증**: 이 프로토타입에는 로그인이 없음. 프로덕션 어드민은 반드시 별도 인증(운영자 계정, 역할 기반 권한)을 두어야 함.
5. **한줄평 스팸/악성 대응**: 비로그인 익명 작성이므로 서버 단 rate limit, 금칙어 필터, 신고 기능 등을 추가로 고려(이 핸드오프 범위 밖이지만 운영상 필요할 가능성 높음).
6. **제보 딥링크 방식**: `?detail=<id>` 쿼리 파라미터 패턴은 실서버에서도 그대로 유지 가능(예: `/content/:id` 라우트로 치환 권장 — SEO/공유에도 유리).

### 데이터 스키마

**Content item**
| 필드 | 타입 | 설명 |
|---|---|---|
| id | number | PK |
| title | string | 제목 |
| category | string | 카테고리 관리에서 정의한 값 중 하나 |
| country | '국내' \| '해외' | 필터용 |
| countryDetail | string | 표시용 국가명(예: "한국", "일본") |
| year | number | 연도 |
| creatorLabel | '감독' \| '연출' \| '작가' | 제작자 구분 |
| creatorName | string | 제작자 이름 |
| leads | string[] | 출연·주인공 이름 목록 |
| tags | string[] | 장르/특징 태그 |
| juice | boolean | "착즙"(서브/약한 GL 코드) 여부 |
| poster | boolean | 포스터 이미지 사용 여부(false면 "포스터 준비중" 텍스트 타일) |
| synopsis | string | 줄거리 |
| platforms | {name, type:'무료'\|'유료', **url**}[] | 시청/감상처 — **url이 있으면 사이트에서 클릭 시 새 탭으로 이동** |

**Category**: `string` (이름 자체가 식별자). 프로덕션에서는 `{id, name, sortOrder}` 형태 권장.

**Submission (제보)**
| 필드 | 타입 |
|---|---|
| id, title, category, country, juice, url, note, contact | 사용자가 제보 폼에 입력한 값 |
| status | 'pending' \| 'approved' \| 'rejected' |
| createdAt | timestamp(ms) |

**Comment (한줄평)** — 플랫 배열, itemId로 콘텐츠와 연결(로그인 사용자 정보 없음)
| 필드 | 타입 |
|---|---|
| id, itemId, text, createdAt | — |
| status | 'visible' \| 'hidden' |
